Pilot owner-led review with a small set of in-repository checks, using the existing owners, Git history and CI. Start from manual review as the baseline and record what the checks add. This tests a useful, bounded change while keeping factual judgments with people. It is a recommendation based on available capabilities, not measured superiority.

The deciding tradeoff is how much uncertainty the first pilot adds. A gives an existing human baseline; B contributes narrow, inspectable signals. C and D are serious alternatives, especially if search or drafting proves expensive, but today's descriptions do not establish that either will reduce omissions or total review effort. No-action retains the current unknown miss rate and produces no new evidence; a bounded review cycle is more useful if owners can participate.

The proposed pilot uses a small document area with a named owner and recent relevant repository changes. Scope is an explicit reversible assumption: use one review cycle first, with no new hosted service and no automatic publication. Keep ordinary editing and publication in the team's existing human-controlled process.

The Git-change list goes to the document owner, who records initially suspected updates. Then reveal the local-link and public-interface flags from B and record which add actionable information. The owner checks factual meaning against the source change and relevant decision context, prepares or requests corrections, and records dispositions. This sequencing gives a rough view of incremental discovery; it is not a controlled performance study. There is no new platform, agent service or ownership layer in this architecture.

The pilot is complete when its record contains the reviewed document scope and change window, confirmed stale passages or broken links, rejected signals and reasons, any updates missed by the first manual pass, review effort, and final owner dispositions. Each claimed correction needs an inspectable source basis. A retrospective check of the selected change set can identify additional misses; misses outside that scope remain unknown. Do not report accuracy or general recall from the number of accepted flags.

Continue A+B only if B adds useful findings or reduces effort enough to justify its maintenance and review noise. If it contributes little, retain A and remove the unnecessary check coverage. If owners can identify relevant changes but struggle to locate passages, compare C with manual search on the same bounded examples. If finding the affected passages is easy but drafting consumes time, compare D's drafts with owner-written corrections and record factual errors and total reviewer effort.
